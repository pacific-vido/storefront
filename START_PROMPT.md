# Первый промпт для Cursor Agent

Создай работающий frontend-каркас MVP приватного видеосервиса. Сначала прочитай .cursor/rules. Если проект уже существует, сохрани его рабочую структуру и зависимости; не пересоздавай проект поверх него.

Стек: Next.js App Router + TypeScript strict + Tailwind CSS. Backend позже будет отдельным Nest.js API с PostgreSQL. Первое размещение планируется на Railway. Будущее мобильное приложение — React Native. Сейчас не подключай backend, базу и реальную видеоинфраструктуру и не выполняй деплой.

Используй FSD lite по правилам проекта. Создай docs/decisions.md с принятыми решениями и docs/current-task.md с границами текущей задачи. Выбери совместимые стабильные версии, зафиксируй их lockfile; не обновляй существующие major-версии без необходимости.

Продукт: пользователь хранит видео в приватных комнатах и бесплатно приглашает зрителей. Комната определяет доступ. Плейлисты внутри комнаты организуют видео и наследуют доступ, собственных настроек доступа нет. Видео можно оставить без плейлиста. Один пользователь владеет своими комнатами и смотрит приглашённые. Платежей и подписок в MVP нет.

Рабочее название pacific-vido вынеси в shared/config. Pacificvido ещё не утверждено. Интерфейс для аудитории США — на английском; комментарии и отчёт мне можно на русском.

Дизайн делаем по ходу. Основной референс https://app.athletesocean.com/home. Нужен спокойный тёмный кабинет: боковая навигация, карточки комнат и видео, заметная Upload-кнопка, удобный плеер. Если референс не открылся, прямо скажи это и следуй описанию. Не копируй чужие бренды. Tailwind — основной styling; globals.css небольшой, никаких огромных CSS-файлов.

Реализуй маршруты:
- /login — demo-вход с выбором одной из двух вымышленных персон, без ввода настоящего пароля.
- /rooms — вкладки My rooms и Shared with me, поиск по названию, создание комнаты через dialog.
- /rooms/[roomId] — описание, вкладки Videos, Playlists и Access; Access только у владельца.
- /rooms/[roomId]/videos/[videoId] — плеер и список видео выбранного плейлиста или комнаты; проверка принадлежности видео комнате.
- /settings — только локальные настройки demo-профиля.

Демоданные: два пользователя, три комнаты с разными владельцами и правами, несколько плейлистов и видео. В data layer добавь типизированные модели и async repository interfaces. Fixtures изолируй в demo-реализациях; компоненты не должны обращаться к ним напрямую. Демо-изменения можно хранить в памяти до обновления страницы; сообщи об этом в README. Не включай настоящий публичный доступ.

Действия: создать/переименовать комнату; добавить/изменить плейлист; менять порядок его видео; симулировать загрузку с progress и состояниями processing/ready/error; повторить неудачную операцию; удалить demo-видео с подтверждением; симулировать приглашение и отзыв доступа. При смене demo-пользователя UI и repository должны проверять права. Зритель не редактирует данные. Отзыв доступа должен отражаться и на просмотре после переключения пользователя.

Для плеера используй HTML video с локальным небольшим лицензированным sample при его наличии. Если sample нет, покажи явное demo-состояние без выдуманного работающего воспроизведения. Upload не отправляет реальные файлы: симулирует метаданные и статусы. Ошибки unknown room, forbidden и unknown video обрабатываются отдельно, чужие данные не отображаются.

Учти адаптивность 375/768/1440 px, keyboard navigation, focus, labels, dialogs, loading/empty/error состояния. Не добавляй тяжёлые анимации, Redux, сложную аналитику, социальные функции и заглушки оплаты.

Безопасность с первого шага: нет реальных секретов и credentials, нет unsafe HTML, данные валидируются, demo-режим явно отмечен. Клиентские проверки demo не являются защитой реального сервиса — объясни это в README. Для production эти проверки будут дублироваться и обеспечиваться Nest.js. Не утверждай, что выполнен production security audit.

Порядок: сначала краткий план и дерево каталогов, затем реализуй каркас в рамках этого задания. Создай npm scripts typecheck/lint/build и check, а также доступный cross-platform архитектурный check для импортов слоёв и ограничений CSS. Не подменяй проверки командами, которые всегда возвращают успех. Проверяй каждую найденную ошибку и исправляй причину. Напиши минимальные meaningful tests для изоляции комнат, невозможности изменения данных зрителем, наследования прав плейлистом и отзыва доступа в demo repository.

Проверь typecheck, lint, build и тесты. Если browser tooling доступен, проверь основные сценарии и три ширины; если нет — явно укажи ограничение. Подготовь README с запуском, демосценариями, ограничениями и следующим шагом интеграции Nest.js. Railway пока только учти в docs: будущие web/API/DB отдельные сервисы, env через Railway, без зависимости от локального диска для постоянных видео.

Обязательно следуй .cursor/rules/40-testing.mdc: unit-тесты для всей сложной domain-логики, включая чужие ID, viewer mutation denied, наследование прав, отзыв доступа, повторное принятие приглашения, удаление видео из плейлистов и upload status/retry. Используй fake timers для симуляций. Добавь test:unit в однократном режиме и включи его в check. Не ограничивайся happy path и не подменяй саму тестируемую логику mocks.

В конце выдай список созданного, команды запуска, результаты реально выполненных проверок и что остаётся demo. Не добавляй задачи следующих этапов в текущую реализацию.
