# Pacificvido

Рабочий frontend-каркас приватного видеосервиса. Название не утверждено и меняется в `src/shared/config/index.ts`.

Человек хранит видео в комнатах и бесплатно приглашает зрителей. Комната задаёт доступ. Плейлист только упорядочивает видео внутри комнаты и своих прав не имеет. Видео можно оставить без плейлиста. Один человек бывает владельцем своих комнат и зрителем чужих.

Это демо. Здесь нет Nest.js, базы, настоящей авторизации и настоящей загрузки видео.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Страница входа — `/login`.

Проверки:

```bash
npm run check
npm run build
```

`check` один раз запускает unit-тесты, typecheck, lint и архитектурную проверку. Сборка — отдельно.

## Демосценарии

Два вымышленных человека, без пароля:

- **Avery Chen** — владелец Coastal Briefings и Field Notes. Jordan уже смотрит Coastal Briefings. На Field Notes для Jordan висит приглашение. У Avery есть приглашение в Harbor Reviews.
- **Jordan Hale** — владелец Harbor Reviews и зритель Coastal Briefings.

1. Войдите как Avery. На My rooms найдите комнату через поиск и создайте новую.
2. На Shared with me примите приглашение в Harbor Reviews.
3. Откройте Coastal Briefings. На Videos нажмите Upload. Файл никуда не уходит: демо читает только имя, размер и тип. Имя с `fail` (например `fail-clip.mp4`) завершится ошибкой; Retry доводит симуляцию до Ready. Обычное видео тоже станет Ready.
4. Готовое видео открывает плеер. Все готовые ролики играют один и тот же короткий CC0-клип, это не загруженный файл.
5. На Playlists поменяйте порядок кнопками Up и Down. На Access отзовите доступ Jordan.
6. В боковой колонке переключитесь на Jordan. Coastal Briefings исчезнет из списка. Прямой адрес комнаты покажет отказ и не покажет её содержимое.
7. Под Jordan примите приглашение в Field Notes на вкладке Shared with me.
8. В Settings поменяйте отображаемое имя.

Обновление страницы стирает сессию и все демоизменения.

## Ограничения

- Данные только в памяти вкладки. Это не база и не сервер.
- Проверки прав в браузере — симуляция. Их можно обойти из инструментов разработчика. В production Nest.js должен повторять и обеспечивать их на каждом запросе: просмотр, списки и изменения. Скрытая кнопка доступом не является.
- На экранах есть пометка DEMO. Настоящих видео, паролей и секретов здесь нет.
- Неизвестный room, чужой room и чужое video — разные ошибки. Чужие названия и списки не возвращаются.
- `npm audit` показывает предупреждения в цепочке ESLint (`braces`), а не в демоданных. `npm audit fix --force` не запускался: он предлагает откатить конфигурацию ESLint до Next.js 14. Это не production security audit.
- Референс https://app.athletesocean.com/home открылся маркетинговой страницей, без кабинета после входа. Макет сделан по описанию задачи.

## Следующий шаг

Отдельная задача: Nest.js API и PostgreSQL. Комнаты, видео, плейлисты и приглашения проверяются на сервере при каждом запросе. Экраны остаются, демо-репозиторий заменяется клиентом API.

На Railway позже будут отдельные сервисы web, API и базы. Переменные окружения задаются там. Постоянные видео не хранятся на локальном диске инстанса.
